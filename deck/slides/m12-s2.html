Research finding · May 2025

A public issue, a private leak

What happened

Invariant Labs showed that a malicious issue in a public GitHub repository could hijack a developer’s AI agent through the GitHub MCP server. The agent copied data from private repositories into a public pull request.

Your situation: Your engineers’ agents read public issues and can write to every company repository using one token.

Your call · 15 min

  1. Spot the toxic mix: untrusted input, private data, a way out.
  2. Which of the three do we cut first?
  3. Should one token ever span public and private work?

MODULE 12

RAG & MCP Security

6 of 10

Concept tested: the "toxic flow" or lethal trifecta: an agent that reads untrusted content, can access private data, and has a channel to send data out. Any agent with all three can be turned into a leak. Model answer. 1) Untrusted input: public issues. Private data: private repositories. Way out: creating a public pull request. 2) Usually the easiest leg to cut is access: split tokens so an agent working on public issues cannot read private repositories. Adding approval for anything published publicly cuts the exit as well. 3) No; scope tokens per repository or per task. Leadership point: ask of every agent, "does it have all three legs?" If yes, it needs an explicit risk decision.
