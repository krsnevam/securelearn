Trust boundary

Any point where trust or ownership changes hands: user to agent, agent to tool, company to vendor.

Runtime trust validation

Trust is re-checked as context changes during a task, never granted once at login.

MODULE 10

Enterprise Trust Architecture

4 of 10

This slide covers curriculum topics 3, 5, 6, 7, 8 and 10: trust boundaries, context trust, tool trust, agent trust, data trust and runtime trust validation. The key idea is that each kind of trust needs a check that happens while the agent is working, not only when it is set up. Ask participants: for one of your agents, which of these four checks happens today, and where in the architecture? The most common answer is "data, partially", which is why the attack modules that follow focus on context, tools and agents.
