The support ticket that opened the vault

What happened

General Analysis showed a support ticket carrying hidden instructions. A developer’s coding agent, connected through the Supabase MCP server with a full-privilege key, read secret tokens from the database and posted them back into the ticket.

Your situation: Your support engineers use an AI agent with database access to investigate customer tickets faster.

Your call · 15 min

  1. What access does this agent actually need?
  2. Read-only, a separate key, or human approval?
  3. Which tickets should it never read automatically?

MODULE 12

RAG & MCP Security

6 of 10

Concept tested: least privilege on MCP servers and context poisoning through tool data. A customer-written ticket is untrusted input, yet the agent ran with a key that bypassed all database security rules. Model answer. 1) Read access to the specific tables needed for support, never secrets or credentials tables. 2) All three: a read-only, restricted key for the agent; a separate break-glass process for anything more; and human approval before the agent writes back to a customer-visible channel. 3) Treat all customer-submitted text as untrusted; at minimum, the agent should never act on instructions found inside a ticket. Leadership point: the convenience of "just give it the admin key" is the root cause in a large share of agent incidents.
