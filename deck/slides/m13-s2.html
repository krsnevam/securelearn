Real case · Aug 2025

Malware that used your own AI tools

What happened

In the “s1ngularity” attack, compromised Nx packages on npm carried malware that ran developers’ own AI coding tools to search their machines for secrets. Thousands of stolen credentials were then published in public GitHub repositories.

Your situation: AI coding assistants are now standard in your SDLC, often with broad file and terminal permissions.

Your call · 15 min

  1. What permissions should AI coding tools get by default?
  2. Which pipeline gates would catch this?
  3. How fast can we rotate every developer secret?

Source: Nx security advisory and analyses by Wiz and StepSecurity, August 2025

MODULE 13

Secure Productization & Lifecycle

7 of 10

Concept tested: the secure AI SDLC. This was among the first malware to weaponise AI assistants already installed on victims' machines, running them with permission-skipping flags. Model answer. 1) Least privilege: no permission-skipping modes by default, workspace-only file access, and no access to credential stores; dangerous modes require explicit approval. 2) Dependency pinning and lockfiles, scanning for malicious packages, blocking install scripts where possible, and secret scanning on commits and public repositories. 3) Keep an inventory of developer secrets and rehearse rotation; prefer short-lived credentials so stolen ones expire quickly. Leadership point: productivity tools with broad local access become attack tools once anything malicious runs on the machine.
